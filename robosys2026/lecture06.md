## テストとは

- プログラムが意図通りに動作するかを<span style="color:red">別のプログラム（テストコード）を書いて</span>テストすること<br />　
- 次のようなテストコードを書いて実行
    1. テスト対象のコードに引数や標準入力からデータを入力
    2. 出力を記録
    3. 期待した出力と一致するか比較　

<center>面倒だと思いますか❓</center>

## 今日のゴール: このテストコードを書けるようになる

```bash
#!/bin/bash
ng () {                             # ④ 違っていたら報告する
        echo ${1}行目のテスト失敗
        res=1
}
res=0
out=$(seq 5 | ./plus)               # ① plusに入力して動かし、② 出力を記録する
[ "${out}" = 15 ] || ng "$LINENO"   # ③ 期待した出力と比較する
[ "${res}" = 0 ] && echo OK         # ④ 全部通ったら報告する
exit $res                           # ④ 結果を機械にも伝える
```

```bash
$ ./test.bash      # plusが正しいとき
OK
$ ./test.bash      # plusがおかしいとき
8行目のテスト失敗
```

## 1. シェルの変数（部品②: 出力を記録する）

---

### 基本事項

- シェルは`変数名=文字列`で文字を記憶
    ```bash
    ### 例 ###
    $ X=我々は宇宙人だ   # 変数のセット                                             
    ```
- `${変数名}`で値に置換
    ```bash
    ### 例 ###
    $ echo ${X}ぜ！      # 変数を値に
    我々は宇宙人だぜ！
    $ echo $X            # {}は省略できる（直後が英数字や_でなければ）
    我々は宇宙人だ
    $ echo '$X' # 値にしないときはシングルクォートで囲う（``と混同注意）               
    $X
    ```
    ```bash
    ### {} が省略できない例 ###
    $ echo ${X}Z
    我々は宇宙人だZ
    $ echo $XZ              #変数「XZ」と解釈されるのでなにも出力されない                      
    ```

---

### コマンドの出力を変数に

- `変数名=$(コマンド)`
 - 通常は標準出力に出るコマンドの出力を文字列として変数に格納<br />　
 - 例: `ls`の出力を変数`A`に　　　　　　　　　　　　　　
    ```bash
    $ A=$(ls)
    $ echo $A
    README.md plus_stdin  # 注意: 出力は各自異なります。
    ```
- ゴールのコードの`out=$(seq 5 | ./plus)`はこれ

## 2. コマンドの終了ステータス（部品③④: 成功・失敗の判定）

---

### コマンドによる正常終了・異常終了の伝達

- コマンドは人に対してだけでなく、シェルにエラーの有無を伝達
    - <span style="color:red">終了ステータス</span>と呼ばれる整数値で伝達
        - 例: `0`なら正常終了、`1`や`2`など`0`以外なら異常終了
        - シェルは<span style="color:red">`?`</span>という特殊なパラメータ（読み出し専用の変数のようなもの）にコマンドの終了ステータスを記録<br />　
     - 例: `ls`の出力
        ```bash
        $ ls /etc/passwd   # 存在するファイルをls
        /etc/passwd
        $ echo $?          # ?に$をつけると値に置き換わる
        0                  # ?の値はゼロ
        
        $ ls aaaaaaaa      # 存在しないファイルをls
        ls: 'aaaaaaaa' にアクセスできません: そのようなファイルやディレクトリはありません
        $ echo $?
        2                  # ゼロでない値が入る。
        ```

---

### `plus_stdin`の終了ステータス

- これまで書いてきた`plus_stdin`も終了ステータスをシェルに伝達
    - Pythonが裏でやっているので任せておいて問題ない
    ```bash
    $ seq 3 | ./plus_stdin    # 正常な入力
    6                         # 正常な答え
    $ echo $?                 # 終了ステータスを表示
    0                         # 終了ステータス0: 正常

    $ echo あ | ./plus_stdin  # ひらがなを入力してエラーを起こさせる
    （エラーの表示。省略。）
    $ echo $?                 # 終了ステータスを表示
    1                         # ゼロでない値が入る
    ```

## 3. テストコマンド（部品③: 期待した出力と比較する）

- やりたいこと: コマンドの出力を入れた変数（例: `out=$(seq 5 | ./plus)`）の値が、期待した出力になっているかチェック
    - → <span style="color:red">テストコマンド</span>で文字列を比較<br />　
- 書き方: `[ 比較したい文字列 = 比較したい文字列 ]`
     - 変数は<span style="color:red">ダブルクォート</span>で囲む: `"$a"`（値に置き換わる）
     - 例
        ```bash
        $ a=鈴木
        $ [ "$a" = 鈴本 ]       # [ ] = の前後には必ず空白（[ もコマンドの一種）
        $ echo $?               # 終了ステータスで確認
        1

        $ [ "$a" = 鈴木 ]
        $ echo $?
        0
        ```

## 5. シェルの関数（部品④: 違っていたら報告する）

- 基本的な関数の書き方: 名前のうしろに`()`をつけて、`{}`の中に処理を記述
- 第`n`引数を`${n}`で受け取り
    - 例: `ng`という関数を作り、呼び出してみる（ファイル名は`test.bash`）
    ```bash
    #!/bin/bash
    
    ng () {                        # 関数ngの定義
            echo ${1}行目のテスト失敗 # $1はngの1番目の引数                                
    }
    
    ng 123                         # 関数ngを呼び出す（123が$1に入る）
    ```
    - 実行
    ```bash
    $ ./test.bash
    123行目のテスト失敗
    ```

--- 

### コマンドと関数の連携

- `[`が失敗したら`ng`を呼び出す
    - 例（ファイル名: `test.bash`）
    ```bash
    #!/bin/bash
    
    ng () {                          # 関数ngの定義
            echo ${1}行目のテスト失敗   # $1はngの1番目の引数 
            res=1                    # 追加: 失敗したことを記録
    }
    
    res=0                            # 0: 失敗なし（ngが呼ばれると1になる）
    a=鈴木
    [ "$a" = 鈴本 ] || ng "$LINENO"  # LINENOはこの行の行番号の入る変数         
    [ "$a" = 鈴木 ] || ng "$LINENO"  # 失敗したら関数ngを呼び出す（$LINENOの値が$1に入る）
    
    exit $res     # このシェルスクリプトの終了ステータスを返して終了
    ```
    - `||`（OR記号）: 左側のコマンドが異常終了したら右側を実行

## 6. テストを書く

部品を組み立てて`plus`をテスト

- 準備: `plus_stdin`を`plus`に改名しておく$\rightarrow$<span style="color:red">コミットを</span>
    - 注意: テストと無関係です。

---

### コードを書く前に: 期待する動作を表にする

- `plus`に何を入れたら、何が出てきてほしいか？

| 入力 | 期待する出力 | 終了ステータス |
|---|---|---|
| `seq 5`（1〜5の整数） | `15` | 0 |
| `あ`（計算できない値） | （何も出ない） | 1 |
| 空行（何も入力しない） | （何も出ない） | 1 |

- この表が`plus`の<span style="color:red">仕様</span>（こう動くべきという約束）
- <span style="color:red">テストコード = この表を機械が読める形に書き直したもの</span>
    - 表の1マスがテストコードの`[ ... ] || ng "$LINENO"`の1行になる
    - まずは1行目（正常な入力）から書いてみる

---

### コマンドに対するリグレッションテストの記述

- 準備: さきほどの`test.bash`をリポジトリ直下（`plus`と同じところ）に置いてコミットしてGitHubにpush
- 次のように`test.bash`を変更（次ページ）
   - うまく動かないときはシバンを`#!/bin/bash -xv`にすると、各行の実行の様子が表示される

---

```bash
#!/bin/bash
# SPDX-FileCopyrightText: 2026 Taro Suzuki
# SPDX-License-Identifier: BSD-3-Clause

ng () {                               # 関数ngの定義（P18と同じ）
        echo ${1}行目のテスト失敗
        res=1                          # 失敗したことを記録
}

res=0                                  # 0: 失敗なし（ngが呼ばれると1になる）

out=$(seq 5 | ./plus)                  # 表の1行目: plusの出力を変数outに記録
[ "${out}" = 15 ] || ng "$LINENO"      # 期待する出力（15）でなければngを呼び出す

[ "${res}" = 0 ] && echo OK            # 通ったのが（人間に）分かるように表示
exit $res                              # 終了ステータスを返して終了（機械向け）
```
- 2〜3行目: 前回学んだ著作権とライセンスの設定（名前は自分のものに！）
- `&&`（AND）: 左のコマンドの終了が正常なら右側を実行

---

### 動作確認

```bash
### 実行権限をお忘れなく ###
$ ./test.bash      # テストを実行
OK                 # 人間向け: テストがすべて通った
$ echo $?          # 機械向け: 終了ステータスを確認
0                  # 0: テスト成功（失敗があれば1）
```

- `plus`への入力を変えるなどして`echo $?`で`1`と出ることも確認

<center>動作確認が終わったら再度テストが通るように戻してGitHubにpush</center>

---

### なぜ判定に終了ステータスを使うのか

- `OK`や`13行目のテスト失敗`という表示は<span style="color:red">人間</span>向け<br />　
- `exit $res`で返す終了ステータスは<span style="color:red">機械</span>向け
    - 人間がいなくても、機械（GitHub）が「テストに通ったかどうか」を判定できる
    - 次回GitHubにpushするたびにテストを自動で実行させます
